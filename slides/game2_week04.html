なぜスキャン？

「作る」前に「取り込む」

モデリングなしで、本物の形と色が手に入る

Blender で作るのは第6回から。今日は自分の楽器や身の回りのモノを、そのまま 3D モデルにします。写真（と距離センサー）から形と色を計算する技術を 3D スキャンといいます。ゲーム・映画の背景、博物館の文化財のデジタル化などで使われています。

「現実の空間に、音を置く」の最初のかたち

秋学期の総合制作のテーマです。モノ ＋ 音 ＋ AR の3つが今日はじめてそろいます。今日のシーンがそのまま、総合制作の「たたき台」になります。

Scaniverse を入れる

STEP ①　Scaniverse

無料の 3D スキャンアプリ「Scaniverse」

iPhone（iOS）Android
入れる場所App Store「Scaniverse」Google Play「Scaniverse」
対応機種iOS 16.6 以降・A12 チップ以降（iPhone XR／XS 以降）。LiDAR は無くても OK（写真から作る）Android 7.0 以降・メモリ 4GB 以上・ARCore の Depth API 対応機（Galaxy S・Pixel など）
料金・言語無料（アプリ内課金なし）。日本語表示あり（このスライドの名前は英語表示のもの）
書き出せる形式OBJ・FBX・GLB・USDZ・STL・PLY・LAS　→ Unity には FBX で持っていく
作っている会社Niantic Spatial（Pokémon GO の Niantic の、地図・空間部門）

Android で「このスマートフォンは対応していません」と出た人、スマホを使わない人は、iPhone の人と一緒にスキャンして FBX をもらう（AirDrop ／ 共有）か、先生のスキャンデータを使います。

サインインを求められても、今日の範囲（スキャンと書き出し）には不要です。地図への投稿（Upload to map）はオフのままにしておきましょう。

STEP ①　2つのモード

Mesh と Splat ― 今日は「Mesh」

Mesh（メッシュ）― 今日はこちら

  • 三角形の面（ポリゴン）と、貼り付けた写真（テクスチャ）でできたふつうの 3D モデル
  • FBX で書き出して Unity・Blender でそのまま使える
  • Collider や当たり判定もつけられる（第5回のタップで使う）

Splat（ガウシアン・スプラット）

  • 小さな「ぼやけた玉」を何百万個も重ねて、写真のような見た目を再現する新しい方式
  • きれいだが、Unity 2022 の AR ではそのまま使えない（専用のパッケージが要る）
  • 今日は使わない。興味があれば発展で

Scaniverse は起動時や新規スキャンのときに Splat ／ Mesh を選びます。必ず Mesh を選んでください（Splat で撮ると FBX にできません）。

②

スキャンする

STEP ②　対象を決める

何をスキャンする？ ― 向くモノ・向かないモノ

◎ 向いている

  • 手のひら〜椅子くらいの大きさ
  • 動かないモノ（置いて撮れる）
  • 表面に模様や色の変化がある（革・布・木・印刷物）
  • 例：楽器ケース、スニーカー、マグカップ、ぬいぐるみ、本の山、椅子、観葉植物

△ 苦手

  • 光るもの・透明なもの（金管楽器、ガラス、ペットボトル）→ 穴があく・ゆがむ
  • 真っ黒・真っ白で模様がないもの（黒いスピーカー、白い壁）
  • 細いもの（譜面台、ケーブル、弦）→ 消える
  • 動くもの（人・動物）、風で揺れるもの
人の顔・他人の持ち物・他人の部屋はスキャンしない。教室でスキャンするときは、まわりの人が写り込まない向きで。
STEP ②　スキャンの手順

Mesh → ゆっくり一周 → Detail → Save

1
「＋」（New Scan）→ Mesh を選ぶSplat ではなく Mesh。大きさを聞かれたら Small Object（椅子くらいなら Medium）
2
モノを机や床の真ん中に置き、● で開始LiDAR の iPhone Pro の人は Range を、モノが入るぎりぎりまで短く（背景を拾わない）
3
モノのまわりを、ゆっくり一周（1〜2分）30〜50cm 離れて、画面の中にモノを入れたまま。赤い縞が消えたところ＝撮れたところ。低い位置と高い位置で2周すると上面も撮れる
4
■ で停止 → 処理の種類は「Detail」小物向けの高画質モード（写真から計算、1〜5分待つ）。Speed は部屋向けで粗い
5
「Save」→ 名前をつける英数字で（例：guitarcase）。Unity でファイル名になる

図は画面を簡略化したものです。ボタンの名前や並びはバージョンで少し変わります（日本語表示なら「新規スキャン」「メッシュ」「小さい物体」など）。処理の種類の選択が出ない機種は、そのまま進めば OK。

STEP ②　コツと失敗例

きれいに撮るコツ

こうなった原因直し方
穴があく・裏が無い撮れていない角度がある低い位置と高い位置で2周。赤い縞が残っていないか確認してから停止
ゆがむ・2重になる動きが速い／モノが動いたゆっくり。モノは置いたまま、自分が動く
ボコボコ・ザラザラ暗い／光る面／模様がない明るい場所で。光るものは布の上に置く。処理は Detail
背景まで入ったRange が長い／周りが近いRange を短く。あとで Crop（次のスライド）
処理が終わらない撮りすぎ（5分以上）1〜2分で止める。スキャンは短くても十分

撮りすぎないのがコツです。1〜2分でぐるっと一周、上からも一周。足りなければ撮り直したほうが早い。

STEP ②　仕上げ

Crop で、机や床を切り落とす

処理が終わったスキャンを開く›Edit›Crop

やること

  • モノを囲む箱の面をドラッグして、机・床・まわりの景色を外に出す
  • 箱の形は四角（Box）と丸（Cylinder）を切り替えられる
  • 下の面はモノの底ぎりぎりまで。机の板が残ると AR で「机ごと」置くことになる
  • 終わったら保存（Done ／ Save）

切らなくてもいい場合

  • 「机の上の風景ごと」置きたいなら、そのままで OK
  • 部屋をまるごとスキャンした（Large Object）場合も、まずはそのまま
  • 細かい修正（穴うめ・軽量化）は Blender の回（第6回〜）でやります

Scaniverse には明るさ・コントラストの調整もあります。暗く撮れたときは少し明るくしておくと、Unity でも見やすくなります。

STEP ③　書き出し

1
スキャンを開いて「Share」（共有）画面の下か右上の共有アイコン
2
「Export Model」→「FBX」形と写真（テクスチャ）が1つのファイルに入る。GLB は Unity 2022 がそのまま読めないので選ばない

Unity に読み込む

STEP ④　読み込み

Models フォルダに入れて、Extract Textures

STEP ④　シーンに置く

AR Template Scene に置いて、大きさを確かめる

1
Scenes の AR Template Scene をダブルクリックで開く（前回作ったシーン。game2_a なら Stage1）
2

音をつける

STEP ⑤　音の素材

どの音をつける？ ― ファイルを Assets に入れる

今日はまずこれ：game2_a の .wav

  • 第3回で配った game2_a の Assets/sound に、ループ用の .wav が入っている
  • Finder でその .wav を、自分のプロジェクトの Assets に作った Audio フォルダにドラッグ
  • game2_a をそのまま使っている人は、もう入っている

慣れたら：自分の音

  • 使える形式：.wav ・ .mp3 ・ .ogg ・ .aiff（Unity 2022.3）
  • iPhone の「ボイスメモ」は .m4a → そのままでは入らない。Mac の「ミュージック」に入れて「MP3 バージョンを作成」（設定 → ファイル → 読み込み設定を MP3 に）
  • 「そのモノが出す音」「その場所で聞きたい音」を考えてみる。ループ素材だと切れ目が気にならない

総合制作では「その場所にあるからこそ意味のある音」を考えます。今日は仕組みを動かすのが目的なので、音はなんでも OK。

STEP ⑤　AudioSource

スキャンしたモノに AudioSource をつける

1
Hierarchy でスキャンしたモノを選ぶ（例：guitarcase）
2
Inspector 一番下の Add Component → 「Audio Source」検索欄に audio と打つと早い

AudioClip の欄に、Audio フォルダの音をドラッグ

これは第3回配布 game2_a の Stage3 の Cube と同じ設定です（迷ったら Stage3 を開いて見比べる）。Doppler Level はそのままで OK（音の高さがフラフラするときは 0 に）。

音に「場所」ができる ― Spatial Blend と距離

Audio Listener は Main Camera に

AR のカメラ＝スマホ＝自分の耳。AR テンプレートの Main Camera には最初から Audio Listener がついています（シーンに1つだけ）。

STEP ⑤　Play で確認（XR Simulation）

まず仮想の部屋で ― 近づくと大きく、離れると消える

1
▶ Play目の前（1m 先、床のあたり）にスキャンしたモノが出て、音が鳴り始める。見えなければ少し見回す

⑥

プログラムで動かす
― 音像も一緒に動く

STEP ⑥　しくみ

音像の位置 ＝ AudioSource が付いている GameObject の位置

1
Unity は毎フレーム、方向と距離から音を作るカメラ（Audio Listener）から見た AudioSource の方向で左右の音量差、距離で大きさを決める（前のスライド）
2
だから、GameObject を動かせば音像も動くスクリプトで transform.position を毎フレーム書き換えると、モノと一緒に音が移動する。音のための特別な処理はいらない
3
今日は「自分のまわりを回す」AR を始めた場所を中心に、半径 1m の円をゆっくり回る。音は 右 → 前 → 左 → 後ろ と回る

Unity 標準の 3D サウンドは左右の音量差（パン）と距離による減衰です。前後・上下の区別は弱いので、イヤホンで「左右に回る」感じを聴きます（本格的な立体音響は Spatializer プラグインの世界）。

STEP ⑥　スクリプト

OrbitSound.cs ― 円を描いて回す

using UnityEngine;

// スキャンしたモノを、AR を始めた場所のまわりで回す。AudioSource（音像）も一緒に回る
public class OrbitSound : MonoBehaviour
{
    public float radius = 1.0f;   // 円の半径（m）
    public float speed  = 30f;    // 1秒に進む角度（度）。マイナスで逆回り
    public float height = 0f;     // 耳の高さからの上下（m）

    float angle = 0f;                // 今の角度（度）

    void Update()
    {
        angle += speed * Time.deltaTime;                        // 角度を少しずつ進める
        float rad = angle * Mathf.Deg2Rad;                      // 度 → ラジアン
        float y = Camera.main.transform.position.y + height;    // カメラ（耳）と同じ高さ
        transform.position = new Vector3(Mathf.Cos(rad) * radius, y, Mathf.Sin(rad) * radius);
    }
}
transform.positionこのモノ（と、付いている AudioSource）の位置。毎フレーム書き換えるので、Inspector で入れた Position は使われなくなる
Mathf.Cos ／ Mathf.Sin角度から、半径 radius の円の上の x・z を計算する（三角関数）
Time.deltaTime前のフレームからの時間。どの機械でも同じ速さで回る（第3回の RotateCube と同じ）
Camera.mainMainCamera タグのカメラ＝AR のカメラ＝耳。その高さに合わせるので、スマホでも仮想の部屋でも目の高さを回る
STEP ⑥　付けて Play

スクリプトを作って、スキャンしたモノに付ける

1
Project の Assets を右クリック → Create → C# Script → 名前 OrbitSoundファイル名とクラス名を同じにする（春学期と同じルール）
2
ダブルクリックで VS Code → 中身を全部消して、前のスライドのコードを貼る → Cmd + S
3
Unity に戻って数秒待つ。Console に赤いエラーが無いか見る
4
Hierarchy のスキャンしたモノを選び、OrbitSound を Inspector にドラッグ（または Add Component → OrbitSound）
5
▶ Play：モノが自分のまわりをゆっくり回る。音も一緒に回るイヤホンで聴くと分かりやすい。矢印キーで見回して、音のする方を追いかける
6
Radius・Speed・Height を変えて試すSpeed -30 で逆回り、90 で速く。Height -0.5 で足元、1 で頭の上（Play 中に変えた値は戻る）

ここまでが今日のゴールです。「置く → 音 → 動く」がそろいました。音が回っているところを画面録画（Cmd + Shift + 5、マイクをオン）しておきましょう。

AudioSource の Spatial Blend が 3D（1）になっていないと、どこに動いても同じ音量＝回って聞こえません。回らないときは、まずここを確認。

往復させる・ドップラー効果を聴く

using UnityEngine;

// 1m 前を、左右に行ったり来たり。音が左右に振れる
public class SwingSound : MonoBehaviour
{
    public float width = 2f;   // 左右に動く幅（m）
    public float speed = 1f;   // 速さ（m／秒）

    void Update()
    {
        // PingPong：0 〜 width を行ったり来たり
        float x = Mathf.PingPong(Time.time * speed, width) - width / 2f;
        float y = Camera.main.transform.position.y;
        transform.position = new Vector3(x, y, 1f);
    }
}
A
往復：SwingSound を作って、OrbitSound の代わりに付ける両方付けると位置の取り合いになるので、OrbitSound は外す（コンポーネントの ⋮ → Remove Component）。1m 前を左右に往復し、音が左右に振れる
B
ドップラー効果：Width 6・Speed 5、AudioSource の Doppler Level を 5 に目の前を通り過ぎるとき、音の高さが下がる（救急車のサイレンと同じ）。Unity は動く AudioSource の速さから自動で計算している
C
自分で式を変えるOrbitSound の y に Mathf.Sin(rad) * 0.3f を足して上下にも揺らす、radius を少しずつ大きくして遠ざける、など

ドップラー効果の強さは AudioSource の Doppler Level（0〜5）と、Edit → Project Settings → Audio の Doppler Factor で変えられます。普段は 1 のままで OK。

今日のまとめ

第4回のまとめ

  • Scaniverse（無料・LiDAR 不要）で身の回りのモノを 3D スキャン → Mesh で撮り、Detail で処理、Crop で机を落とす
  • FBX で書き出して AirDrop → Unity の Models フォルダ → Materials タブの Extract Textures で色がつく。大きさは実寸
  • AR Template Scene の Cube の代わりに置く（Position 0, 0, 1）
  • AudioSource：Play On Awake・Loop・Spatial Blend 3D・Linear・Min 1 ／ Max 2 → 近づくと聞こえる音
  • 音像の位置 ＝ GameObject の位置。スクリプト（OrbitSound）で transform.position を毎フレーム動かすと、音も一緒に回る
  • XR Simulation で確認 → できた人はスマホで（Bundle Identifier・Scenes In Build）

スキャンした .fbx と今日のプロジェクトは、消さずに取っておいてください。第5回はこのシーン（置く → 音 → 動く）の続きから始めます。
