Section 01

前回の復習（stage3-1）

Sphere を転がして Cube を消す

復習：Sphere の操作

Rigidbody + AddForce で転がす

Rigidbody rb; void Start() { rb = GetComponent<Rigidbody>(); } void Update() { if (Input.GetKey(KeyCode.RightArrow)) rb.AddForce(Vector3.right); if (Input.GetKey(KeyCode.LeftArrow)) rb.AddForce(Vector3.left); if (Input.GetKey(KeyCode.UpArrow)) rb.AddForce(Vector3.forward); if (Input.GetKey(KeyCode.DownArrow)) rb.AddForce(Vector3.back); }

Sphere に Rigidbody を付け、Tag を「Player」に設定。矢印キーで転がせるようになる。

復習：衝突で消す

OnCollisionEnter で Tag を判定

void OnCollisionEnter(Collision collision) { if (collision.gameObject.CompareTag("Player")) { Destroy(gameObject); // 衝突したオブジェクト（自分）を消す } }
  • OnCollisionEnter：物理衝突した瞬間に呼ばれる関数
  • CompareTag("Player")：相手のタグが Player のときだけ処理する
  • Sphere が衝突してきたら Cube が消える ＝ シンプルな当たり判定の完成
Section 02

Prefabとは何か（stage3-2）

再利用可能なオブジェクトの設計図

Prefab の概念

「設計図」からオブジェクトを量産する

  • Prefab ＝ オブジェクトの「テンプレート（設計図）」
  • 形・コンポーネント・スクリプト設定をまるごとファイルとして保存できる
  • Prefab からシーンに配置したオブジェクトを「インスタンス」と呼ぶ
  • 1つの設計図から何個でもインスタンスを作れる

Prefab がないと…

同じ Cube を10個置きたいとき、1個ずつ手動で作成・設定が必要。変更するときも1個ずつ…

Prefab があると…

設計図を1回作るだけ。あとは何個でも配置できる。変更も設計図1カ所を直すだけでOK！

Prefab 作成

HierarchyオブジェクトをProjectにドラッグ

1
シーンに Cube を用意するHierarchy 右クリック → 3D Object → Cube を追加
2
Project に「Prefabs」フォルダを作るProject 右クリック → Create → Folder → 名前を「Prefabs」に
3
Hierarchy の Cube を Prefabs フォルダにドラッグ青いキューブアイコンのファイルが作成されれば成功！
4
Hierarchy の Cube の文字色が青に変わる青い文字 ＝ Prefab のインスタンスのサイン
Material（マテリアル）

オブジェクトに色を付ける

1
Project に「Materials」フォルダを作成アセットを整理する習慣を付ける
2
右クリック → Create → Material名前を付ける（例：Blue / Green）
3
Inspector の「Albedo」横のカラーボックスをクリックカラーピッカーで色を選ぶ
4
Material を Prefab にドラッグ「B_Cube」「G_Cube」のように色違いの Prefab が作れる

Prefab に Material を適用すると、その Prefab から生成されたすべてのインスタンスに色が反映される。

Prefab の編集

全インスタンスに変更を反映させる

1
Project の Prefab ファイルをダブルクリック「Prefab 編集モード」に入る（Scene 背景が変わる）
2
この状態で変更を加える例：Scale や Material を変更する
3
Scene ビュー上部の「＜ Back」で戻る変更がすべてのインスタンスに反映される！
⚠ インスタンス側を個別に変更しても、その変更は Prefab には反映されません（インスタンス固有の変更になる）。
Section 03

Instantiateで生成する（stage3-3）

スクリプトから Prefab を呼び出す

Instantiate

Prefab をゲーム中に生成する

  • Instantiate(prefab, position, rotation)：Prefab を指定位置・回転で生成
  • ゲーム実行中に何度でも呼び出せる ＝ 弾・敵・アイテムの量産に使う
  • 生成するためには、まず「Prefab を入れる箱（変数）」を用意する
  • 変数の型は GameObject、Inspector からドラッグして紐付ける

Prefab を「設計図」、Instantiate を「印刷ボタン」と考えると分かりやすい。押すたびに同じ物が出てくる。

Player スクリプト

Space キーで弾を発射する

public GameObject bullet; // 弾のプレハブ void Update() { if (Input.GetKeyDown(KeyCode.Space)) { // 弾のプレハブを生成する（位置はプレイヤーの少し前、回転はなし） Instantiate(bullet, transform.position + Vector3.forward * 2, Quaternion.identity); } }
  • public GameObject bullet：Inspector で Bullet プレハブをドラッグして設定
  • transform.position + Vector3.forward * 2：プレイヤーの2マス前から発射
  • Quaternion.identity：回転なし（そのままの向き）を意味する書き方
Bullet スクリプト

毎フレーム前方へ進める

public class Test3_3_bullet : MonoBehaviour { void Update() { transform.Translate(Vector3.forward * 0.1f); } }

弾の Prefab にこのスクリプトを付ければ、Instantiate で生成された弾は自動で前進する。

⚠ Bullet スクリプトは Prefab 側に付けること（Hierarchy のインスタンスではなく Project の Prefab ファイル）。そうしないと次に生成された弾には付かない。
Section 04

敵を撃って消す（stage3-4）

Tag と衝突で敵を破壊する

Player の操作を拡張

左右移動 + Space で発射

public GameObject bullet; void Update() { if (Input.GetKeyDown(KeyCode.Space)) { Instantiate(bullet, transform.position + Vector3.forward * 2, Quaternion.identity); } if (Input.GetKeyDown(KeyCode.RightArrow)) transform.position = transform.position + Vector3.right; if (Input.GetKeyDown(KeyCode.LeftArrow)) transform.position = transform.position + Vector3.left; }

今回は GetKeyDown を使っているので、押した瞬間にカクッと1マスずつ動く。なめらかに動かしたい場合は GetKey + Translate に変えると良い。

Bullet（強化版）

当たったら消える弾にする

void Update() { transform.Translate(Vector3.forward * 0.1f); } private void OnCollisionEnter(Collision collision) { Destroy(gameObject); // 何かに衝突したら自分を消す }
  • 前回学んだ OnCollisionEnter を使って自分自身を破壊する
  • Tag を絞らずに「何かに当たったら消える」シンプル実装
  • Bullet と Enemy のどちらにも Collider が必要（Cube ならデフォルトで付いている）
Enemy

敵も衝突で消す

public class Test3_4_enemy : MonoBehaviour { private void OnCollisionEnter(Collision collision) { Destroy(gameObject); // 衝突した瞬間に自分を消す } }

Enemy も Prefab 化しておけば、シーンに複数並べたり、後の回で「ランダム生成」もできるようになる。

⚠ Player には Tag「Player」、Enemy には Tag「Enemy」を必ず設定しよう。今後、判定を「敵だけ消す」「プレイヤー以外消す」のように分けるときに使う。

まとめ

今日学んだこと
